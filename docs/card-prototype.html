🛡️ 三、飞书卡片能力约束与本原型替代处理说明

本原型 100% 可直接无损翻译为飞书卡片 JSON 2.0，不包含任何飞书无法实现的技术特效
飞书能力限制项 飞书原生真实边界 传统 Web 设计常犯错误 本原型的合规替代方案
主题与文字颜色 Header template 仅支持 red/orange/blue/green/grey 等枚举；文本只支持加粗、行内代码与少数 font color。 使用任意 Hex 颜色、高亮 Badge、多彩渐变色。 严格遵守 “颜色只表状态”：红表示完全不可用或凭证断裂；橙表示逼近阈值；蓝/灰表示正常，不给正常数字上彩色。
图表与进度条 无原生进度条组件（Progress bar），无 SVG/Canvas 渲染能力。 在卡片内画 CSS 进度条或伪元素。 直接展示严谨的百分比数字与窗口名称（如 周窗口 100.0%、最紧 41.0%），保全证据确凿性。
操作按钮行为 卡片按钮仅支持 open_url（链接跳转）与 callback（回传异步事件）。 设计“重新登录弹窗”、“停用凭证”等带业务破坏性副作用的表单。 仅提供两个安全无状态按钮：刷新额度（重新拉取）与 去 CPA（仅在出现失效凭证时跳转管理端）。
卡片纵向空间预算 飞书对卡片 payload 大小有 25KB 严格上限，超限会被服务端直接丢弃拒绝发送。 无限向下罗列全部账号的所有细分 token 窗口。 采用折叠汇总行；健康渠道 1 行带过；在极端多异常时通过“另有 X 个未展开，用 @我 <渠道>”优雅折叠。
