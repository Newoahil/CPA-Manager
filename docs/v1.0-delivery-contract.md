### 屏蔽分组（`QUOTA_IGNORED_GROUPS`）

- **只在渲染层生效。** 代码里有三处调用 `FilterMessage`（`render/render.go:448`）：
  - `render/card.go:57`
  - `render/text.go:18`
  - `notify/webhook/webhook.go:131`
- 屏蔽的匹配方式：
  - 窗口：按分组名比较（`render.go:341`）；
  - 告警：只匹配 `Scope == group` 的告警（`render.go:384-392`）。
- **不影响判断层。** `internal/evaluate` 和 `internal/app` 都没有读这个配置，屏蔽分组照样会被判定、写进状态、生成告警，只是在渲染时被过滤掉。由此带来三个后果，都列在第 7 节：
  1. 一批告警如果全部属于屏蔽分组，会推送出一张全量额度卡；
  2. 快速轮询会被屏蔽分组的窗口触发；
  3. 冷却告警的范围是模型（model），不是分组（group），所以屏蔽分组拦不住它。
- **配置来源有两个：**
  - 飞书机器人显式传入 `cfg.QuotaIgnoredGroups`（`feishu/feishu.go:87`）；
  - `render.New` 自己也直接读环境变量（`render.go:106`）；webhook 不传参数，用的就是这条路径。
- **默认值：** `Claude and GPT models`（`config/config.go:140`）。

### cooldown（`internal/cooldown/cooldown.go`）

**数据来源**
- 只读 CPA 的凭证列表接口：v8 是 `/v8/management/credentials`，v0 是 `/v0/management/auth-files`。入口是 `main.go:135`：`SetCooldownLister(cpaClient.ListCredentials)`。
- 不请求任何上游额度接口。
- 读取的字段：`unavailable`、`next_retry_after`、`cooldowns[]`（`scope`、`model_key`、`reason`、`retry_at`、`http_status`）。解析代码在 `internal/cpa/credentials.go:33-106` 和 `client.go:499`。
- 解析时的保护：
  - 冷却字段格式错误时，只丢弃这一项，不会让整个凭证列表解析失败；
  - 字符串最多保留 128 个字符；
  - **从不读取 `status_message`**，因为它可能原样带着上游返回的内容。

**处理逻辑**
1. 每个冷却片段按「凭证 + scope + model_key」区分（`cooldown.go:109`）。
2. 跳过 disabled 凭证（`:168`）。
3. 满足以下任一条件即告警，每个片段只告警一次（`:224-229`）：
   - 冷却已持续 ≥ `COOLDOWN_ALERT_AFTER`；
   - CPA 给出的恢复时间离首次发现 ≥ `COOLDOWN_ALERT_AFTER`。
4. 告警过的片段结束时，发一条「限流解除」告警。
5. 没告警过的短片段，计入每个凭证的汇总（次数、最长时长），日报取走后清零（`:233`、`app.go:427`）。

**告警格式**
- 告警类型：`AlertRateLimited`、`AlertRateLimitCleared`（`domain/types.go:470-471`）。
- Facts 前缀：`状态码:`、`预计恢复:`（RFC3339 UTC 时间）、`持续:`（如 `5m`）（`types.go:478-480`、`cooldown.go:270-316`）。
- 告警批次进 outbox，和额度告警一样享有至少一次投递（`app.go:369-398`）。

**额度用满的判定**（只在渲染层，`render/alertnotice.go:303`）
- 如果恢复时间比告警发生时间晚 30 分钟以上，卡片显示为「额度用满」，而不是「限流冷却中」。
- 依据是 CPA 自身的退避上限为 30 分钟。这是一条启发式规则，见第 7 节。

**状态保存**
- 冷却片段**只存在内存里**，进程重启后清零，见第 7 节。

## 5. 飞书侧契约

### 卡片回调（`feishu/handler.go:188-276`）

**处理流程**
1. 去重：按 `cardEventKey` 生成键（`parse.go:91`），有事件 ID 就用事件 ID，否则用「消息 ID + action」。去重表容量 512，有效期 10 分钟（`dedup.go:13-14`）。重复的回调返回提示「该操作已处理」。
2. 路由：`actionName` 读取 `value.action`（`parse.go:106`），然后进入 `:217-226` 的 **if 分支链**：
   - `noop`：返回空响应。圆角行容器 `interactive_container` 要求必须带一个回调，所以每一行都会发这个空动作（`render/blocks.go` 中的 `NoopAction`）。
   - `refresh_quota`：继续处理。
   - 其他值：返回提示「该操作不支持」。
3. **先应答、后异步：** 立即返回提示「正在刷新额度...」，然后在 `taskGroup` 里执行 `serveCardRefresh`（`:251`）：
   - 采集预算用 `messageBudget`，30 秒（`:28`）；
   - 用 `patchCard` 原地更新卡片，发送预算 2.5 秒（`feishu.go:32`、`:168`）；
   - 采集失败且没有缓存时，把卡片更新成「实时采集失败」。
4. `refreshBudget` 字段（`feishu.go:48,91`）现在已经不用了。

**现有 action：** `refresh_quota`、`noop`，没有别的。

**v2.0 加「批准 / 拒绝」：** 现在**没有 action 注册表**，新 action 只能在 `handler.go:217-226` 里加分支。建议 v2.0 先把这段 if 链重构成「action → handler」的映射，再往映射里注册新 action。注意：
- **v1.0 已经取消了会话限制。** 现在任何会话发来的回调都会被处理，没有任何人员授权。批准这类写操作必须另外加操作人白名单，并做二次确认。
- 一张卡片同一个 action 只处理一次，去重键是「消息 ID + action」。审批卡如果要允许多次操作，需要换一种去重键。

## 6. 不变式与约束

**基本约束**
- **只读：** 不调用任何会修改 CPA 状态的接口。按钮只有只读的「刷新额度」和外链「去 CPA」。
- **单副本：** 状态文件和 outbox 只能由一个进程写，飞书长连接也只能有一个实例（`feishu/run.go:18-22`、README）。
- **缺失的数值不当作 0 或 100：** `remainingPctOrUnknown` 显示为「未上报」，进度条显示为灰色空条（`render/blocks.go:697`）。
- **scope 未知时，不下全账号结论：**
  - 判断层把 scope 未知的窗口记为 `ScopeUnknown`（`evaluate/scope.go:31-33`）；
  - 渲染层标注「（范围未知）」，并且不给出建议（`summary.go` 中的 `grade`）。
- **401 / 403：**
  - CPA 管理接口返回认证错误时，健康检查改为每 5 分钟一次，其他情况按指数退避，最长 15 分钟（`main.go:52-54,255-268`）。
  - 上游返回 401，判定为凭证失效；403 和 429 都按网络问题处理，不作判定（`quota/quota.go:157-164`）。
- **429 永远不判定为额度耗尽：** `quota.go:161`。只有冷却时长超过 30 分钟时，渲染层才把它显示为用满。
- **不泄露敏感信息：** 不渲染 `Snapshot.Err` 原文，不读取 `status_message`，凭证只显示别名。

**v1.0 新增的规则**
- 渠道状态按**还能用的号**来判断：一个号用满、其他号还有余量时，不会标红，也不会写「额度告急」（`blocks.go:279`、`:372`，`card.go:1164`）。
- 显示的都是剩余百分比，保留 1 位小数；阈值仍然按已用百分比判断。
- 窗口统一命名为 `5h` / `7d`，排序为 5h、7d、其他；同一个模型组的窗口排在一起（`card.go:424-490`）。
- 证据不足时，告警必须标「疑似」（`alertnotice.go:352`）。
- 只影响某个模型或分组的变化，必须写「仅 …」；恢复不能写成全账号恢复（`alertnotice.go:249`）。
- 卡片的硬性限制：
  - `collapsible_panel` 里不能放 `table`；
  - 完整卡的 `config` 只有 `update_multi` 和 `width_mode: compact` 两项，简版卡只有 `update_multi`（`card.go:82`）；
  - `column_set` 不写 `horizontal_spacing`；
  - 单张卡最多 200 个组件。
- 完整卡被飞书拒收时，必须能自动改发简版卡（`feishu.go:128`）。简版卡里不能出现 `interactive_container`、`collapsible_panel` 和 chart。

## 7. 未完成 / 已知问题 / 风险

**已知缺陷（代码中未修）**

1. **屏蔽分组的告警会推送出一张全量额度卡。** `FilterMessage` 把告警清空之后，`isAlertNotice` 返回 false，于是渲染成整张查询卡。`feishu.go:118` 和 `webhook.go:131` 都没有判断「告警被过滤后为空就不发」。
   - 修法：在 `Notify` 里，原消息有告警、过滤后为空时直接跳过。
2. **卡片回调对任何会话都有效，也没有人员授权**（`handler.go:217`）。现在只有只读刷新，风险不大；v2.0 加写操作前必须先解决。
3. **屏蔽分组不影响判断层。**
   - 快速轮询（`app.go:308`）会被屏蔽分组的窗口触发。
   - Antigravity 下 Claude 模型的冷却告警，scope 是模型而不是分组，所以屏蔽分组拦不住（`render.go:384-392` 只匹配分组）。
